# Технічна документація: Підключення до MSSQL та Робота з Сервером

Даний файл містить повну інструкцію для розробників щодо налаштування підключення мобільного додатка до бази даних MSSQL через сервер-проксі (API), специфікацію API та пояснення обмежень тестування у хмарному середовищі AI Studio.

---

## 1. Архітектурна схема взаємодії

Мобільний додаток побудований за принципом **Offline-First**. Це гарантує безперебійну роботу навіть за умов відсутності інтернету:

```
[Аудіозапис] ───> [Локальна БД Room] ───> [WorkManager (Фон)]
                                                   │
               ┌───────────────────────────────────┴──────────────────────────────────┐
               ▼ (Зв'язок є)                                                          ▼ (Зв'язок відсутній)
[Надсилання WAV на API Сервер]                                              [Локальна розшифровка через Gemini]
               │                                                                      │
               ▼                                                                      ▼
  [Обробка / Whisper]                                                      [Збереження результату в Room]
               │                                                                      │
               ▼                                                                      ▼
 [Запис тексту в MSSQL через API]                                        [Черга на надсилання при оновленні]
```

Оскільки Android за стандартами безпеки не працює з базами даних (як-от MSSQL) напряму через пряме TCP-з'єднання (через безпеку, обмеженість пулу потоків та потенційне розкриття паролів у коді), **взаємодія здійснюється через проміжний API-сервер (REST API Proxy)**.

---

## 2. Що необхідно для підключення до MSSQL (Вимоги до БД)

Для успішного збереження транскрибацій у вашій базі даних MSSQL необхідно підготувати таблицю та налаштувати права доступу для вашого Проксі-сервера (як-от Node.js, C#, Python або PHP-бекенд).

### А. Структура таблиці в MSSQL
Створіть таблицю (наприклад, `Transcriptions` або аналогічну) із наступними полями:

```sql
CREATE TABLE Transcriptions (
    Id INT IDENTITY(1,1) PRIMARY KEY,
    UserId NVARCHAR(120) NOT NULL,          -- Унікальний ID менеджера (напр. "Менеджер_01")
    ClientName NVARCHAR(250) NOT NULL,      -- ПІБ чи ID клієнта
    Timestamp BIGINT NOT NULL,              -- Час створення запису (Unix Epoch у мілісекундах)
    Transcription NVARCHAR(MAX) NOT NULL,   -- Повний розпізнаний текст розмови
    Language NVARCHAR(10) NOT NULL,         -- Мова розмови (напр. "uk" або "ru")
    CreatedAt DATETIME DEFAULT GETDATE()    -- Час фактичного запису в MSSQL
);
```

### Б. Налаштування доступу користувача
Переконайтеся, що ваш API-сервер підключається до MSSQL за допомогою логіну, який має права:
*   `INSERT` у таблицю записів.
*   `READ` (якщо планується синхронізація історії назад на пристрій).

## 3. Специфікація API: Надсилання даних на сервер

Мобільний додаток відправляє запити на адресу сервера, яку користувач вказує у вкладці **"Налаштування"** (наприклад, `https://your-api-domain.com/`). Додаток підтримує два схеми роботи:

### Схема А: Пряме завантаження аудіо на сервер (Очікування обробки)

Якщо на сервер відправляється запис голосу для розшифрування серверними потужностями:

#### 1. Завантаження аудіофайлу
*   **Ендпоінт**: `POST api/upload`
*   **Тип вмісту**: `multipart/form-data`
*   **Параметри запиту**:
    *   `audio` (файл): Аудіозапис розмови у формати `.wav` (PCM 16kHz mono).
    *   `userId` (текст): Ідентифікатор менеджера.
    *   `clientName` (текст): ПІБ або ID клієнта.
    *   `language` (текст): Обрана мова розпізнавання (`uk` або `ru`).
*   **Очікувана відповідь від сервера (HTTP 200/202)**:
    ```json
    {
      "taskId": "a1b2c3d4-e5f6-7890-abcd-112233445566",
      "status": "processing",
      "message": "Файл успішно завантажено. Починаємо обробку."
    }
    ```

#### 2. Опитування статусу обробки (Polling)
Додаток автоматично опитує сервер про статус розпізнавання кожні кілька секунд.
*   **Ендпоінт**: `GET api/status/{taskId}`
*   **Очікувана відповідь від сервера (HTTP 200)**:
    *   **Під час обробки**:
        ```json
        {
          "taskId": "a1b2c3d4-e5f6-7890-abcd-112233445566",
          "status": "processing",
          "transcription": null,
          "message": "Обробка триває"
        }
        ```
    *   **Після завершення**:
        ```json
        {
          "taskId": "a1b2c3d4-e5f6-7890-abcd-112233445566",
          "status": "completed",
          "transcription": "Добрий день! Чим можу допомогти?...",
          "isDiarized": false,
          "message": "Розшифрування успішне"
        }
        ```

---

### Схема Б: Надсилання вже локально розшифрованого тексту (Fallback режим)

Якщо зв'язок із сервером тимчасово був відсутній, або конфігурація сервера не відповіла, додаток **самостійно робить локальну транскрибацію за допомогою вбудованого Gemini API**. 

Після успішної локальної транскрибації запис отримує статус `SAVED_LOCAL` (Збережено локально). Як тільки зв'язок відновлюється і користувач натискає **"Оновити"**, додаток передає вже готовий до роботи текстовий результат:

*   **Ендпоінт**: `POST api/transcription`
*   **Тип вмісту**: `application/json`
*   **Тіло запиту (JSON)**:
    ```json
    {
      "userId": "Менеджер_01",
      "clientName": "Іванов Іван Іванович",
      "timestamp": 1718973600000,
      "transcription": "Текст розмови, розшифрований локально через Gemini API",
      "language": "uk"
    }
    ```
*   **Успішна відповідь від сервера (HTTP 200)**:
    ```json
    {
      "success": true,
      "message": "Дані успішно збережено в базі даних MSSQL"
    }
    ```

## 4. Чому ви не можете протестувати додаток безпосередньо в середовищі розробки AI Studio?

Під час роботи з веб-версією Google AI Studio ви можете бачити помилки завантаження або відсутність доступу до мікрофона. Це зумовлено технічними особливостями ізольованого середовища (Sandbox):

1.  **Відсутність реального мікрофона в контейнері**:
    Віртуальний пристрій (Емулятор Android) запущений віддалено на серверах Google у хмарі. Оскільки фізичний мікрофон вашого комп'ютера не підключений безпосередньо до віртуального аудіовходу сервера через веб-інтерфейс у реальному часі, додаток записує порожню аудіодоріжку (тишу) або викликає помилку ініціалізації аудіовходу (AudioRecord init failed).
2.  **Обмеження мережі (CORS та Локальні IP)**:
    Сервери Google AI Studio знаходяться за глобальним мережевим екраном (Firewall). Якщо ви намагаєтеся підключитися до сервера розшифровки чи бази даних, запущеної на вашому локальному комп'ютері (`localhost`, `127.0.0.1` або сірі IP-адреси на кшталт `192.168.1.5`), хмарний емулятор **фізично не зможе надіслати запит на ваш комп'ютер**.
3.  **Необхідність публічної HTTPS адреси сервера**:
    Для безпечного зв'язку (Network Security Config в Android) додаток вимагає підключення лише через зашифровані канали `https://`. Якщо ваш бекенд-сервер запущений без SSL-сертифіката (`http://`), Android блокуватиме запити для запобігання перехопленню інформації.

### Як правильно протестувати додаток:
1.  **Встановити реальний APK**: Завантажте готовий APK на свій реальний смартфон через меню налаштувань проєкту ("Export APK"). На реальному пристрої мікрофон та запис звуку працюватимуть на 100%.
2.  **Використовувати публічний API або тунелі**: Опублікуйте свій API-сервер в інтернеті з HTTPS-сертифікатом або скористайтеся інструментами тунелювання (наприклад, **`ngrok`** чи **`Cloudflare Tunnels`**), щоб отримати безкоштовну тимчасову HTTPS адресу виду `https://random-subdomain.ngrok-free.app` та впишіть її в Налаштуваннях додатка.
